# idea_context/ — provided definitions & reference material

Drop the client's real inputs here: a functional/technical spec, business rules, a prior PRD, mockups, Figma exports, PDFs, screenshots, sample code.
At the requirements/design phases Aitri injects the full text of the readable files here into the agent's briefing, and flags what it cannot read (mockups, PDFs, oversized files) with an instruction to OPEN it — so provided definitions reach the agent, not just their filenames. This material is AUTHORITATIVE input Aitri builds from, not raw material to re-invent.

Notes:
- The seed brief you write is the `aitri/product/IDEA.md` file (the intent) — a different thing; this folder holds the detailed definitions.
- Keep it curated: remove material that becomes obsolete as the project evolves, so it does not mislead the agent.
